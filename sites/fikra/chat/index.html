How this works

01

ZeroGPU

The Space borrows a shared GPU for each reply, then releases it. It works the same on a phone or a laptop — the model runs on the Space, not on your device.

02

Nothing is stored

This page keeps the conversation in memory only. The demo app does not save prompts or replies to a database.

03

Open weights

The model is Apache 2.0. Download the fp16 weights or the 2.71 GB Q4_K_M GGUF and run it on your own machine.

Running on Hugging Face Spaces. The demo shares a daily GPU quota; if it runs out, try again tomorrow or run Fikra locally.

Limits / before you rely on it

What this demo is not.

The model is real. The demo is still a demo. Here is what to expect before you use it for anything important.

01

Shared GPU quota

The live demo runs on a shared daily GPU quota. When it runs out, the demo pauses until tomorrow. Logged-in Hugging Face accounts get a larger quota on the Space itself.

02

Cold starts and mobile tabs

The Space sleeps when idle. The first reply can take up to two minutes while it wakes. On a phone, keep this tab open — backgrounding the browser can drop the connection.

03

Do not paste secrets

Prompts go to a public Hugging Face Space. This page keeps history in memory only, but do not paste passwords, IDs, or private data.

04

It can be wrong

A 4B model will hallucinate on specialized domains. It is not a replacement for retrieval or a curated knowledge base.

05

No live information

Recency stops at the training data. Ask for current prices, news, or law and it may invent an answer.

06

Not offline here

The website demo needs a connection. For offline use, download the Q4_K_M GGUF and run it with llama.cpp on your own machine.
